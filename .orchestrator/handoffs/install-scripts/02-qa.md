## Result

1. Verdict FIX. One requirement fails, in install.ps1 only. The ps1 has no `[CmdletBinding()]` and never checks `$args`, so an unknown switch is silently dropped and the script carries on as a REAL run with exit 0. `-WhatIf`, the standard PowerShell dry-run switch, therefore does a real install. So does a typo such as `-DryRum`, or `-SkipInt` (which then runs init). install.sh rejects unknown flags (exit 2).
   Fix (implementation): put `[CmdletBinding()]` on the line above `param(`. An unknown named parameter then fails parameter binding (exit 1), the same way `-Client foo` already exits 1.

I had not added the safety flags because I expected parameter binding to reject the switch. The run renamed the real `C:\Users\felip\.konnect\bin\konnect.exe` (0.12.0) to `konnect-0.12.0-20260922-100448.exe.bak` and copied my QA fake binary into place.    Restored with the script's own printed rollback (the two `Move-Item` lines), and the parked fake was deleted. The final sha256, mtime and bin listing are byte-identical to my start snapshot (see Evidence 12). `~/.claude/settings.json` mtime is still 2026-09-21. Any Konnect MCP server started between 10:04:48 and about 10:06 would have launched the fake, which exits immediately. If a session reported Konnect failing to start in that window, restarting it fixes it.
3. Every other requirement passes in both scripts. That includes three paths the developer could only read, not run: init/status/Done-count (tested with a fake konnect binary), the build step (tested with a fake cargo), and "copy fails → rename back" (forced).
