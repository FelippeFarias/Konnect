## Result

**38 PASS / 9 FAIL** across 31 task criteria and 16 spec scenarios. One implementation defect makes the whole approval gate
uncallable in production; the other failures are a doc-count criterion that
contradicts its own file and four spec scenarios this change's tasks never
implement.

1. **`save_photo_review_map` cannot be called.** `ToolDef::new` runs
   `close_input_schema` (`tools/mod.rs:134`), which recurses into `properties`
   and inserts `additionalProperties: false`. The `map` parameter is declared as
   a bare `{"type": "object"}` with no `properties`, so the published schema
   accepts `{}` and nothing else — and `{}` is then refused by the handler's own
   `validate_incoming_map`. The MCP dispatcher validates before it dispatches
   (`mcp/handler.rs:366`), so no caller can ever save a review map. Every unit
   test passes because all of them call `handle_save_photo_review_map` directly.
   It is the only one of the 231 registered tools with this shape (E17). Fix:
   declare the map's nested `properties`, or set `"additionalProperties": true`
   explicitly — `entry().or_insert()` preserves it.
2. Task 6.2's second clause (`grep -c "photo_intake" tool-directory.md` ≥ 6)
   returns 2. The file mentions every other toolset 2-3 times; the guard test it
   exists to protect (`doc_tool_counts`) passes. The criterion, not the file, is
   wrong — intent layer.
3. The spec delta's "approved map hands off to real schematic build" (3
   scenarios) and "unapproved map cannot reach schematic build" have no code and
   no runnable check. Design D6.4 deliberately leaves them as prose, and the
   prose lives only in the *delegating* agent:
   `grep -c "approval_valid\|review_map\|photo" assets/agents/kicad-schematic-build-agent.md`
   → `0`. A build agent invoked directly never sees the gate — spec layer.
4. Everything else holds, including the parts that are easy to fake: the scoped
   `HOME` really does keep retrace's stores off the user's home (proved with a
   control run, E14), the pinned content hash is derived independently, and
   `approve_photo_review_map` is the only producer of `approved: true`.
5. Two new test files added and committed (`1fd059e`), both green: the
   end-to-end gate chain through `ToolRouter` + each tool's compiled validator,
   and a permanent guard for task 5.7's second acceptance clause, which the
   developer checked with a throwaway test that was then deleted.
