## For the next agent

1. **Implementation order** — 1.1 → 1.5 → 1.2 → 3.6 → 1.3 → 1.4 → 2.x → 3.1-3.5 → 4.x → 5.x → 6 → 7. `effective_config` (1.5) and `review_map_content_hash` (3.6) are prerequisites of everything that reads config or touches approval; doing them late means rewriting handlers.
2. **Most likely done wrong #1 — the empty-string trap.** retrace emits `""`, never `null`, for `marking`/`part_number`/`datasheet_url`/`value`/`package`. A plain `Option<String>` gives you `Some("")` and the review map then shows a reviewer a filled field that was never read. The deserializer in D1 is not optional, and task 2.2's second test is the one that catches its absence.
3. **Most likely done wrong #2 — the content hash.** Implement `review_map_content_hash` exactly once and call it from all three sites (save, approve, schematic-build re-check). Hash the field-selected object, never the file bytes: the user is *supposed* to hand-edit the JSON, and a whitespace-sensitive hash revokes approval on a reformat, which teaches people to re-approve without looking. `subcircuit_hints` and `saved_at` stay outside it.
4. **Most likely done wrong #3 — assuming the asset suite will pass.** `backticked_tool_names_in_prose_exist_in_the_registry` will fail the moment the new SKILL.md names `used_fallback` or `bbox_px`, and the failure reads like the test being pedantic. 5. **Two things that look optional and are not:** `tool_count: 5` in the `ToolsetMeta` entry (`registry_tool_counts_match_reality` fails without it) and `kill_on_drop(true)` on every `Command` (a timed-out python keeps writing into the scoped HOME and, on Windows, holds a handle that blocks its cleanup).
